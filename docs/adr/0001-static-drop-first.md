# ADR-0001: 静的サイトの匿名ドロップから始める

- ステータス：採用
- 日付：2026-10-17

## 背景

当初は「自分のアプリを Git リポジトリからデプロイする PaaS」を考えていたが、本来の着想は「ブラウザで HTML やプロジェクトをアップロードすると、デプロイされた URL が得られるサービス」だった。

アップロードできるものによって、難しさとリスクが大きく変わる。

| レベル | アップロードするもの | サーバーで起きること | 他人に開放したときのリスク |
|---|---|---|---|
| L1 静的サイト | HTML/CSS/JS、ビルド済みファイル | ファイルを置いて配信するだけ | 低い（主にフィッシング） |
| L2 ビルドあり | Vite/React などのソース | ビルドを実行する | 中くらい（ビルド時に任意コードが動く） |
| L3 サーバーあり | API や Dockerfile | コンテナが常時動く | 高い（任意コードが常時動く） |

## 決定

- 最初のリリースは **L1（静的サイト）** に限定する
- 最初は **匿名ドロップのみ**（ログインなし）。サイトは短時間（1時間）で失効する
- ログインと Claim（匿名サイトを自分のものにする）は後のフェーズで追加する
- L2、L3 は後のフェーズで段階的に追加する。L3 は自分と招待した人に限定する

## 理由

- 「HTML + CSS のサイトを短時間メンバーに共有したい」という具体的な需要に、最小の機能で応えられる
- 他人のコードをサーバーで実行しないため、他人に開放しても現実的に運用できる
- L1 だけでも S3、CloudFront、Route 53、WAF、PostgreSQL、認証などを自然に使える
- L2、L3 に進むと、キュー、Worker、ECS / EKS を使う必然性が生まれる

## 影響

- ECS / EKS に触れるのは後半のフェーズになる
- 匿名で公開するため、悪用対策が必要になる（[ADR-0002](0002-passphrase-gated-launch.md)）
