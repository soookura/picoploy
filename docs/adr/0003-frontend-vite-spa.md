# ADR-0003: フロントエンドは Vite + React（SPA）、API は Hono で分離する

- ステータス：採用
- 日付：2026-10-17

## 背景

TypeScript でフロントエンドとバックエンドを書く。候補は次の2つ。

- **Next.js**：React のフルスタックフレームワーク。画面とサーバー処理（API Routes / Server Actions）を1つのプロジェクトで書ける
- **Vite + React + 別の API サーバー（Hono）**：Vite はビルドツールで、成果物は静的ファイル。API は別に用意する

## 決定

- フロントエンドは **Vite + React（SPA）**
- API は **Hono + Node.js** で別に作る
- モノレポにして、Hono の RPC 機能で API の型をフロントと共有する

## 理由

- この開発の目的はバックエンドを学ぶこと。Next.js は画面とバックエンドの境界を隠してくれるが、それが学びを減らす
- 画面と API が分かれていると、REST API 設計、認証（Cookie / CORS）、バリデーション、エラーハンドリングを、境界を意識しながら学べる
- Vite の成果物は静的ファイルなので、S3 + CloudFront で配信できる。picoploy の思想（静的サイトのホスティング）と一致し、将来は picoploy 自身で管理画面を配信することもできる
- API はコンテナや Lambda に載せられるので、フロントとバックで別々のデプロイ方法を経験できる
- 管理画面のようなアプリでは、SEO のための SSR は不要

## 影響

- フロントと API で CORS やドメイン設計を考える必要がある（学習対象として歓迎）
- ルーティングやデータ取得のライブラリ（TanStack Router / Query など）は実装時に選ぶ
